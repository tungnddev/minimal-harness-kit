# .mhk/repo-map.yaml — shape reference

Generated and consumed by `/mhk:init` and `/mhk:sync` only. It is a **build-time cache for the generator tooling**, not something Claude loads as part of normal session context — the actual runtime memory is `CLAUDE.md` itself, which Claude Code already loads automatically. Keeping this out of the runtime context path is deliberate: it avoids the "one big config file every session has to consider" pattern.

```yaml
version: 1
scanned_at: 2026-07-27T00:00:00Z

repo:
  kind: backend
  language: go
  framework: gin
  package_manager: go modules
  commands:
    install: go mod download
    test: go test ./...
    lint: golangci-lint run
    build: go build ./cmd/api
  claude_md: CLAUDE.md
  rules_confidence_high: 3
  rules_confidence_medium: 1

rules:
  - file: .claude/rules/migrations.md
    kind: cross-cutting        # cross-cutting | reuse-catalog
    paths: ["**/migrations/**"]
    signpost: true             # whether a one-line pointer to this file exists in CLAUDE.md
  - file: .claude/rules/ui-catalog.md
    kind: reuse-catalog
    paths: ["**/presentation/**"]
    signpost: true
    entries: 14                # catalog row count, so /mhk:sync can spot growth/drift

deny_rules:
  - pattern: "Read(./**/*.g.dart)"
    reason: "generated file, regenerated by build_runner"
```

`/mhk:sync` diffs a fresh scan against this file to figure out which parts of CLAUDE.md, which `.claude/rules/*.md` files, and which `permissions.deny` entries actually changed, so it only touches what needs it instead of regenerating everything on every run.
